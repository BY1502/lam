# 단일 모델 GPU 메모리 정책

사용자의 2026-10-27 지시: 모델을 병렬 실행하거나 메모리에 동시에 적재하지 않는다. 남은 평가는 보류한다.

## 현재 상태

Ollama에 적재 모델이 없는 것을 확인한 뒤 **Ollama 컨테이너를 중지**했다. vLLM만 실행·적재한다. 두 API를 함께 열어 둔 상태에서 외부 요청이 모델을 추가 적재하는 경로를 줄인다. Docker 이미지·실행 인자·볼륨·모델 파일·인증·네트워크 설정은 변경하지 않았다.

## 새 전환 순서

1. 평가와 무관한 GPU 작업이 있으면 중단하고 그 작업을 종료하지 않는다.
2. 기존 vLLM은 유휴 확인 후 중지한다. Ollama의 허용 모델은 언로드한 뒤 컨테이너도 중지한다.
3. GPU 프로세스가 없고 각 GPU 사용량이 64MiB 이하인 상태를 두 번 연속 확인한다. 메모리가 남거나 확인이 실패하면 다음 엔진을 시작하지 않는다. 64MiB는 유휴 상태 확인의 보수적 상한이며 모델 동시 적재 허용량이 아니다.
4. 선택한 엔진 하나만 시작하고 준비 상태를 확인한다. 다른 엔진 컨테이너는 중지된 상태를 유지한다.
5. 매 문항 전후 엔진 단독 실행과 Ollama 모델의 이름/개수를 검사한다. 예상하지 않은 적재를 발견하면 다음 문항을 진행하지 않는다. 이미 실행된 원본은 보존하며 정상 성능 측정에서 제외한다.
6. 복원도 같은 해제 확인을 거친다. 예전 초기 스냅샷에 두 API가 함께 실행 중이었더라도 이번에 명시된 단일 엔진 정책을 우선하여 vLLM 적재 상태에서는 Ollama를 중지한다.

같은 Ollama 서버에 다른 클라이언트가 직접 다른 모델을 요청하는 상황까지 애플리케이션 내부 락만으로 완전히 통제할 수 없다. 독점 사용 구간이 확인되지 않으면 평가하지 않는다. 다른 GPU 작업을 강제 종료하거나 이 문제를 숨기지 않는다.

## 변경과 검증

- `evaluation/gpu_safety.py`: 잔류 메모리/프로세스 해제, 연속 확인, 엔진/모델 단독 상태 검사.
- `evaluation/run_classification.py`: 위 검사를 통과한 뒤에만 다음 컨테이너 시작. 보류된 실험의 자동 실행을 거부. 준비 상태 조회는 생성 요청과 구분한다.
- `backend/llm_client.py`: UI에서 Ollama의 단순 미적재만 보고 vLLM을 허용하지 않는다. 실제 로컬 컨테이너 중지를 읽기 전용으로 확인한다. Ollama도 vLLM 컨테이너가 중지됐을 때만 허용한다. 모델 선택은 서비스를 자동 전환하지 않는다.
- 자동 검사27개 통과. GPU가 덜 해제됐을 때 시작 차단, 두 번 연속 해제, 다중 모델 차단 등을 모의 상태로 검증했다.
- 보류 지시를 유지하므로 **실제 모델 전환 평가나 새 생성 요청은 수행하지 않았다.** 실서비스 전환까지 완전히 검증했다고 주장하지 않는다.

기존 결과와 보류/제외 기록은 그대로 보존한다. 안전 로직 변경 뒤의 평가는 기존 소스 해시와 달라지므로, 사용자의 재개 승인과 새 실험 ID가 필요하다. 원래 보류 실험을 조용히 재실행하거나 실패를 덮어쓰지 않는다.
