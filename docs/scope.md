# 범위

이 프로젝트는 새로 작성한 의도 분류 전용 앱이다. 폐기된 프로젝트의 코드·실행기·평가 보고서·저장 자료를 찾거나 복구하지 않는다. 분류 정의와 기본 질문의 유일한 원문은 사용자가 대화에서 직접 제공한 첨부(1~65번), 66번 보완 행, 예상 질문66개다.

질문 → 동일 규칙/정의와 원문을 포함한 메시지 → 선택 구성의 생성 API 한 번 → 엄격한 JSON 검증 → 표시·파일 저장만 구현한다. 계획, 검색, 도구, 예측, 디지털 트윈, 작업 기억은 없다. 모델 전송 차이는 llm_client.py에 모은다. 기대값·예외 질문은 분류기가 읽지 않는다.

평가는 기본66+예외20을 구성별3회 실행한다. 변형16개는 작성만 하고 이번 주 비교에서는 미실행한다. 준비 요청은 별도 저장한다. 오류도 정답률 분모에 포함한다. CPU 오프로딩은 정상 warm 성능 통계에서 제외하며 원본과 오류는 보존한다. 미제공 토큰/세부 시간은 null이다.

번호54는 한 정의가 세척 절차와 수행 이력을 함께 포괄한다. 58은 보관 환경 관리와 기준 이탈 확인(24)의 범위가 겹친다. 엄격한 기대 번호는 실행 전에 고정하고 결과를 보고 바꾸지 않는다. 유효 JSON, 기대 번호 일치, 현장 의미적 적절성은 다른 지표다.

실제 배포 모델의 가중치·양자화·채팅 템플릿이 다르므로 순수 엔진 비교가 아니다. 추론 비활성 Qwen과 think=low GPT-OSS도 동일 계산량이 아니다. 짧은 분류 JSON의 지연은 전체 LAM 답변 지연과 다르다.

원문과 결과, .env, 가상환경은 Git에서 제외한다. 모델 다운로드/컨테이너 재설치/설정 변경은 하지 않는다. 평가 스크립트만 기존 컨테이너를 필요한 동안 stop/start하고 같은 컨테이너의 설정·볼륨을 유지한다. 앱 UI는 모델을 내려버리지 않는다.
